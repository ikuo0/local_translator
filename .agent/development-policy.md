
# システム記号

- CR
  - Customer Requirement
  - 顧客要件
  - 番号形式
    - CR99
- SR
  - System Requirement
  - システム要件
  - 番号形式
    - SR9999
    - 上2桁はカテゴリを示す
    - 下2桁はカテゴリ内機能番号
    - 半分ずつの飛び地で使い、機能が番号順で並ぶように挿入する際に困らないようにする
      - 既存番号が10、20の場合、その間に追加する機能には15を割り当てる、次は13, 17 のように二分して割り当て挿入の余地を確保する
- SF
  - System Feature
  - システム機能項目
  - 大規模開発で細分化する際に SR のサブ機能塊の記号に使う
  - 規模が小さい場合は SR9999 だけで間に合うので SF を使う必要はない
  - 番号形式
    - SF9999
    - 上2桁はカテゴリを示す
    - 下2桁はカテゴリ内機能番号
    - 半分ずつの飛び地で使い、機能が番号順で並ぶように挿入する際に困らないようにする

# コーディングルール

- 関数呼び出しの連続とし、OOPは必要最小限とする
  - クラス解析によるトークン肥大化を避けるため
  - 状態やライフサイクルの管理、外部ライブラリとの整合性など、明確な利点がある場合に限りクラス化を許容する
  - 抽象クラス、継承、デザインパターン等を具体的な必要性なく導入しない
- 関数化ルール
  - １回しか使用しない処理は関数化しない
  - ループ処理を簡潔にする関数化は許容
  - 独立したテストを目的とする関数化は許容
  - 次項の計算・副作用明示のための関数化は必須
- 計算と副作用を分ける
  - 次の順番で処理を関数化する
    - input(副作用)
    - workflow(計算)
    - output(副作用)
  - 探索ループ＋条件処理の場合
    - input(副作用)
    - orchestrator(計算+副作用)
    - output(副作用)
    - この場合も、関数レベルでできるだけリソース（副作用）を切り離した構造にする
  - 純粋機能フォルダ
    - {src root}/libs に実装する
    - このフォルダは副作用（リソースアクセスを含まないという思想）
  - システム機能フォルダ
    - {src root}/features に実装する
    - このフォルダは副作用を含むことが前提（リソースアクセスなど）
    - feature で入力を受け取り libs で処理
  - 副作用概念の注意点
    - 機能として完結している場合にリソースアクセスを含んでもそれは「計算概念」とする場合がある
    - 本概念と矛盾が生じる場合は必ず開発者に確認を取ること
- フォルダ構成
  - {src root}
    - libs
      - {任意の名前ファイル}
    - features
      - SR9999
        - 小規模時は {任意の名前ファイル} で十分
        - 機能が多くカテゴリ分けが必要な時に SF9999_hogehoge.py などで機能分けする
        - 更に大規模になった場合は次の SF9999 フォルダを作成して機能分けする
        - SF9999
          - {任意の名前ファイル}
          - SF9999 は大体の場合で不要、大規模開発の場合のみに使用する
  - pythonファイル構成
    - 次のような構成とし、他からのimport対応を __init__.py 、 単体実行を __main__.py で行う
    - 主機能関数群の実装
      - {module}/{module}/__init__.py
    - コマンドライン実行部の実装
      - {module}/{module}/__main__.py

# 省略表記、ワンライナーの原則禁止

- 可読性のため省略形表記を原則禁止とする
- 初期化など内包表記まで禁止する物ではない

```python
# これが禁止
a = 1 if True else 0

# これが許可
a = 0
if True:
    a = 1

# 例外的に一望しやすい場合にワンライナーを推奨する
# 3個以上の単調処理（引数が違うだけとか）
a = 1 if True else 0
b = 2 if True else 0
c = 3 if True else 0
# みたいな場合にはサマリのようで見やすいのでワンライナーのような省略表記を許可
```

```text
        ├── SR1200/                 # 中規模：SFをファイル単位で管理

        │   ├── SF1220_validate.py
        │   ├── SF1230_execute.py

        │
        └── SR1300/                 # 大規模：SFをフォルダ単位で管理
            ├── __init__.py
            ├── __main__.py
            │
            ├── SF1310/
            │   ├── __init__.py
            │   ├── __main__.py
            │   ├── input.py
            │   ├── workflow.py
            │   └── output.py
            │
            └── SF1320/
                ├── __init__.py
                ├── __main__.py
                ├── input.py
                ├── orchestrator.py
                └── output.py
```
